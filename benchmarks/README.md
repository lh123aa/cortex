# Cortex Benchmark

可复现的 Cortex 检索基准。**任何人都能用同一条命令得到同一组数字**。

## 快速开始

```bash
# 完整流程：生成语料 → 索引 → 检索 → 质量评估
go run ./cmd/cortex-bench all --docs 1000 --workers 8

# 输出到文件
go run ./cmd/cortex-bench all --docs 1000 \
  --out benchmarks/results/latest.md \
  --json-out benchmarks/results/latest.json
```

约 1–2 分钟跑完（1000 文档）。结果同时打印到终端。

## 为什么需要它

之前 README 里的性能数字是手写的，无法复现、无法回归。这个 harness 解决三件事：

1. **可复现**：语料由固定 seed 生成，不依赖任何外部数据集或网络。
2. **可归因**：每个查询都有唯一 ground truth 文档，recall 高低能直接说明问题。
3. **可回归**：数字变化能定位到具体提交，而不是靠体感。

## 指标口径

| 指标 | 定义 | 怎么读 |
|---|---|---|
| 索引吞吐 | 成功索引文件数 / 耗时 | 受文件大小、chunker、磁盘影响 |
| 检索 P50/P95/P99 | 单次 hybrid 查询耗时，**缓存关闭** | 关注 P95，P50 会被小查询拉低 |
| Recall@k | 目标文档进入前 k 的比例 | 分词/索引坏掉时会立刻掉 |
| MRR | 目标文档排名的倒数均值 | 衡量排序，不只是"有没有召回" |
| Top-10 未命中 | 完全没召回的查询数 | > 0 说明存在硬缺口 |

**文档级去重**：一篇文档被切成多个分块时，只按它最高的名次计一次。
否则 top-10 会被同一篇文档的多个分块占满，指标会虚高。

## 三种查询及其作用

| 类型 | 构造方式 | 用途 |
|---|---|---|
| `unique` | 只出现在该文档的标识词 | 测「能不能召回」，正常应接近 1.0 |
| `topic` | 主题词 + 唯一标识词 | 更接近真实自然语言查询 |
| `shared` | 簇内共享词（无唯一答案） | 测「候选等价时排序是否稳定」，**不计入 recall** |

`shared` 查询的候选文档证据完全等价，因此 MRR 与随机基线相当是**预期结果**；
真正有意义的是目标文档是否被召回（containment）。另外，多词查询要求这些词
落在同一个分块里才命中，所以长文档被切块时 containment 天然不会等于 1.0。

## 参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `--docs` | 500 | 语料文档数 |
| `--seed` | 20261023 | 随机种子，同 seed 结果完全一致 |
| `--workers` | 8 | 索引并发数 |
| `--queries-per-doc` | 3 | 1=只 unique；2=+topic；3=+shared |
| `--top-k` | 10 | 检索返回条数（≥10） |
| `--repeat` | 3 | 每条查询重复次数（只影响延迟统计） |
| `--dir` | `_temp/bench` | 工作目录（语料 + 数据库） |
| `--out` | — | Markdown 报告路径 |
| `--json-out` | — | JSON 结果路径 |

每次运行都会**删除旧库和旧语料**，保证冷启动、结果可比。

## 子命令

| 命令 | 说明 |
|---|---|
| `all` | 完整流程（默认推荐） |
| `index` | 只测索引吞吐 |
| `search` | 只测检索延迟 |
| `quality` | 只测召回质量 |

## 诚实边界

- 语料是**合成数据**，不是真实文档。它适合做版本间纵向对比，**不适合**与其他产品横向比较。
- 默认 `embedding.provider = none`，测的是 **FTS-only 混合检索**（BM25 一路）。
  开启 Ollama 后向量路启用，数字会变（需要单独跑并注明配置）。
- 本基准不测 HTTP 层开销。测的是引擎本身（storage + search）。
- 合成语料的分词难度低于真实中文文档（专有名词、缩写、中英混排更少），
  因此 recall 会偏乐观。

## 结果存档

建议每次发版前跑一次并提交结果：

```
benchmarks/results/
  v4.0.0.md
  v4.0.0.json
```

对比两次结果即可判断是否引入性能或质量回归。
