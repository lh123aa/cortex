# 竞品对比：Cortex vs 同类产品

> 数据来源：各项目官网/GitHub 公开信息（2026-10 抓取）+ 本文实测（标注「实测」）
> 原则：**只写能核实的内容**；对方的性能数据一律标注为「官方自测」，因为环境不同不可直接对比。

---

## 1. 一句话定位

| 产品 | 它是什么 | 适合谁 |
|---|---|---|
| **Cortex** | 中文优先、单二进制、MCP 原生的本地知识库 + Agent 记忆层 | 用 Claude Code/Cursor 的中文开发者、小团队 |
| **XERJ** | 本地优先的高性能检索引擎（ES 兼容 + MCP） | 需要引擎级能力、自建检索服务的团队 |
| **AnythingLLM** | 私有化 AI 工作台（桌面/Docker/云） | 想要开箱即用 UI 的非技术用户 |
| **Dify** | LLM 应用编排平台 | 要做 AI 应用的开发者/产品团队 |
| **Open WebUI** | 自托管 LLM 聊天前端 | 想统一接入多家模型的企业 |
| **Mem0** | Agent 记忆 API（托管 + 开源库） | 应用开发者（记忆即服务） |

**Cortex 不与 XERJ 抢引擎市场，也不与 Dify 抢应用编排。Cortex 抢的是「中文用户想给 Agent 装一个能用的记忆/知识库」这个具体场景。**

## 3. 性能对照（量级，非同环境跑分）

| 指标 | Cortex（实测） | XERJ（官方自测） | 说明 |
|---|---|---|---|
| 索引吞吐 | 106–127 files/s | ≈160 files/s（25,329 文件 / 158.1 s） | XERJ 快约 40–50%，且语料更复杂（含二进制解析） |
| 检索 P50 | **1 ms**（27k 文档 / 84k 分块） | 未公开同口径数据 | Cortex 用 FTS 索引，延迟稳定 |
| 冷启动 | **0.36 s**（27k 文档） | 未公开 | Cortex 按需加载，不建大索引 |
| 常驻内存 | 30–70 MB | 未公开 | 个人机器友好 |
| 二进制体积 | 37.4 MB | 未公开（Rust 静态） | — |
| 支持格式数 | ~20 类 | 40+ 类 | **Cortex 的明确短板** |

**结论**：Cortex 在「个人知识库规模」性能足够，与 XERJ 不在同一赛道；索引速度不是 Cortex 的卖点。

## 5. 差异化（只有这四条站得住）

1. **中文优先**：CJK 分词、标题/正文分别分词、9 家 embedding（含 3 家国内）、中文文档。竞品都不专门做。
2. **真·零依赖单二进制**：37 MB，无 CGO、无 Docker、无外部数据库；对比 AnythingLLM/Dify 的容器栈，安装成本低一个量级。
3. **MCP 开箱即用**：14 工具 + `cortex start` 自动写入 Claude Code/Cursor/OpenCode/Trae 配置（带备份与合并保护）。
4. **内置商业化基础设施**：Ed25519 离线 License、配额强制、RBAC 三档、Prometheus、企业版审计（已实现并通过门控验证）。

## 6. 诚实的短板（不要回避）

| 短板 | 事实 | 对外口径 |
|---|---|---|
| 格式少 | `.rs`/`.sql` 直接 failed | 「支持 Markdown/PDF/DOCX/代码/配置，更多格式在路上」 |
| 英文长尾 | 英文查询 P95 ~34 ms | 「中文场景优化更好」 |
| 无 ES 兼容 | 无 `_search` DSL | 「不替代 Elasticsearch」 |
| 无 tree-sitter | 仅 Go 精确 | 「Go 项目体验最佳」 |
| 社区小 | 3 stars / 2 贡献者 | 用「更新频率 + 响应速度」弥补 |
| 规模上限 | 舒适区 ≤3 万文档 | 明确写「个人/小团队」 |
